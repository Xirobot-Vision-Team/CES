# EC336 — Relocated receiver: strict original-path signed-history replay

## Purpose and trust model

EC335 proves copied source and nested ZIP member **byte integrity**, not an old-path-sensitive signature replay. EC336 runs the existing EC333→EC294 verifier on the receiver, with original signed path strings left intact and read-time bytes redirected through the EC317 guarded ORIGINAL reader to byte-identical, individually mapped, owner-private originals. This is an offline *verification context binding*, **not** cryptographic re-signing, substitution of original signed message paths, new source ownership evidence, a trusted new physical path identity, or institutional authorization.

The receiver supplies **six independent whole-raw-SHA claims** obtained and pinned outside the transport itself: EC334 first-hop inventory, EC335 observed-closure document, EC335 source→destination map, and EC333 handoff plus left/right EC331 original manifests. A digest copied out of the very untrusted document whose bytes it describes is *not* an external trust anchor. The three historical root claims must agree with EC334's already recorded root roles. All six may reflect local asserted provenance unless a real custodian independently authenticates them.

**Command:** `scripts/ces_cas_relocated_signed_replay.py verify-signed-replay`; isolated unified option: `scripts/ces_next.py audit-relocated-signed-replay DeliveryAudit VerifyRelocatedOriginalSignedHistory` with identical nine named input options. No writer or source-side command exists for EC336. No key store, host, provider, remote CAS or network access is needed or authorized by this feature.

## Execution sequence, failure containment

1. Validate all nine required fields: three distinct private absolute control file paths, six nonzero lowercase SHA-256 claim strings. Run the unmodified `EC335.verify_copies`, whose checks include external whole-SHA pins of all controls, strict private source/destination map, exact SHA/length of *every* mapped destination original, nested `ZIP_STORED` member chain comparison and late pins. Require its explicit `exit2` with `destination_replay_not_performed=true` rather than promoting that preflight into a signed claim.
2. Load the pinned plan/closure/map with their original canonical readers; select exactly one original handoff, left EC331 manifest and right EC331 manifest by role, bind their six distinct trusted context inputs, and refuse any control/original path alias or any original==destination mapping.
3. Construct `bindings = {historical_signed_source_path: recipient_private_destination_path}` from the **already verified** explicit map. Enter EC317 `_scoped_original_source_reads(bindings, observer)`; no fallback to physical paths of the sender is allowed. The signer-specified path literal remains the argument passed into the old verifier and original cryptographic document parsing; the reader opens the mapped physical destination, protected by `O_NOFOLLOW`, original mode/size/regular-file checks, and the old higher-level canonical SHA and owner checks.
4. Invoke **actual existing** `ec333_replayable_delta_handoff.handoff.verify_handoff` with root historical absolute paths and three caller-supplied root digests. Its EC332, EC331 and historical cascade verify the existing signatures; ensure EC333's explicit result fields attest both signed histories replayed, exact handoff reconstructed, old sources repinned, no prohibited success claims, and `exit2` unresolved. Merely forging these fields without doing the required reads still fails the observer's complete path-coverage check.
5. Every guarded ORIGINAL read is observed under the original logical path name. Persistent reads must be in the EC335 closure and byte-match it; all closure persistent source names must be visited. Verifier-generated private temporary ZIP imports are *not* transported persistent originals, but are allowed only if the verifier has just materialized those **specific** files in a freshly owned `TemporaryDirectory` from verified ZIP contents, under a `ContextVar` that resets on exit. This grant is never prefix-based. Observer counts these import reads instead of silently ignoring them. No unknown persistent original or arbitrary JSON-declared extra path is allowed.
6. Old EC319 registry pre/post file metadata checks run against the exact EC317-mapped physical target inode rather than the absent sender pathname. Every persistent logical ORIGINAL is repinned while the strict scope remains active; every physical destination original and all three canonical pinned controls are repinned again after the scope exits. Final result is a machine-readable **local-only unresolved** proof of verification steps, not a third-party custody attestation or an atomic transaction.

Internal adapters required to make *the same existing old verifier* work with physical originals absent on the receiver: `ec279_finding_query_host.protocol` (ContextVar exact temporary read grants), `ec319_offline_transfer_registry.registry` (metadata on mapped inode), `ec321_fork_case_transport.case`, `ec323_composite_fork_capsule.capsule`, `ec326_conditional_conflict_hold.hold` (explicit lifetime-scoped self-created temporary ZIP imports). They change neither historical signed bytes, cryptographic message domains, Ed25519 checks, old signature syntax nor native PowerShell V4.60/R150.

## Outcomes and interpretation

- **`exit2`** `relocated_guarded_original_bytes_cryptographically_replayed_local_only_unresolved`: real inherited signing validations executed in the recipient's *strictly bound read context*, all EC335 persistent original reads were covered, old signed content/paths were not rewritten, source and nested original bytes/checks and late pins succeeded. This does **not** assert that mapped physical paths were genuinely original, that six root SHA pins came from an independently trusted custodian, or that every dormant historic branch in the world was observed.
- **`exit3`** `permission_denied`: authorization/logic read scope violations, unknown/extra original source, mismatch with declared boundary.
- **`exit4`** `invalid_input`: malformed/incorrect external pins, invalid signed artifact, unsupported zip/source archive, malformed canonical documents. An inherited mock of old EC317/318 deep signing deliberately fails in a real isolated process.
- **`exit5`** `unavailable`: filesystem errors, missing originals or other unavailable historical signing chain resources. The unified wrapper additionally validates child reply schema, positive false-overclaim flags, returned six pins and exit codes; it never upgrades denial to success.

The signed original path literal is still a logical verification domain claim, not an independently verified source OS path identity. TOCTOU/ABA remains possible across multi-file hash/reopen; two per-file reads are not a transactional filesystem snapshot. Private receiver tree governance, independent organizational custodians, true cross-device transport, actually immutable versioned storage, CAS/WORM/readback and actual nonexecution/global latest/winner remain separate engineering and final-acceptance tasks.

## Locally exercised scope

EC336 adds ten focused cases: positive read bridging while all 22 old source files are physically absent, 15 embedded members prechecked, no fallback on mutated or missing destination, six root/control SHA mismatch denials, forged positive-with-no-reads denial, unknown-ORIGINAL denial, exact ephemeral whitelist lifetime, EC319 same-inode metadata, genuine isolated child refusal of inherited MOCK deep signing, and unified read-only action/refusal semantics. Those tests use true local eighth/ninth Ed25519 signing but inherited deep EC317/EC318 structural MOCK. The actual independently isolated CLI must reject that fixture with `exit4`, as observed; there is **no unmocked full EC294→EC336 production positive acceptance** yet. Original PS7 Smoke15 and real two-device custody remain not run. These are deferred rather than replaced by self-contained automated test claims.
