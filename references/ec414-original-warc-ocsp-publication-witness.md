# EC414 original OCSP WARC/1.1 + dual Ed25519 observation evidence contract

**Scope:** The EC414 receiver is read-only. It requires the *unchanged real*
EC413 original issuer-direct signed OCSP audit, through EC412/411/410/409/408/
407 and every previous original verifier, before checking new files. EC414
cannot certify European Commission/OJEU trust anchors, an actual prior HTTPS
network event, historical public availability, institutional independence,
qualified UTC, global revocation or an ETSI/eIDAS legal pass. Distinct keys and
SHA-256 do not establish independent institutional identity or custody.

## Source originals (one to three inherited original EC410 epochs)

Supply a SHA-256-pinned original JSON bundle:

```json
{
  "schema": "ces.ec414.original_ocsp_publication_bundle.v1",
  "claimed_directory_lineage_id": "<unchanged parent lineage>",
  "parent_ec413_original_lotl_ocsp_bundle_original": {
    "path": "<exact original EC413 bundle path>", "sha256": "<sha256>"
  },
  "outside_publication_witness_roster_original": {
    "path": "<roster original JSON>", "sha256": "<separately held roster SHA>"
  },
  "epochs": [{
    "epoch_index": 0,
    "historical": {
      "original_two_ocsp_warc": {"path": "<historical WARC/1.1>", "sha256": "<sha256>"},
      "publisher_signed_receipt_original": {"path": "<publisher signed JSON>", "sha256": "<sha256>"},
      "observer_signed_receipt_original": {"path": "<observer signed JSON>", "sha256": "<sha256>"}
    },
    "evaluation": {
      "original_two_ocsp_warc": {"path": "<evaluation WARC/1.1>", "sha256": "<sha256>"},
      "publisher_signed_receipt_original": {"path": "<publisher signed JSON>", "sha256": "<sha256>"},
      "observer_signed_receipt_original": {"path": "<observer signed JSON>", "sha256": "<sha256>"}
    }
  }]
}
```

For subsequent epochs, either window may be `null` (and then joint credit is
zero); first-epoch windows are mandatory. Neither partial windows nor any
reappearing window after the first missing window are allowed. Later epochs
must match the real EC413 epoch count and ordering. Each WARC and receipt is a
**separate original source file**, not an inline payload generated by receiver.
Source paths and SHA values cannot alias EC413/EC412/EC410 originals or each
other. All read originals are SHA-256-checked again at the end.

The roster has exactly `schema`, `claimed_directory_lineage_id`, `https_origin`,
`publisher`, and `observer`. Its schema is
`ces.ec414.outside_pinned_ocsp_witness_roster.v1`. Both role entries have
exactly `witness_id` (unique identifier matching
`[A-Za-z][A-Za-z0-9_-]{0,63}`) and `public_key_original` (a `{path,sha256}`
reference to the exact **32-byte raw Ed25519 public key**). The keys must be
different and externally SHA-pinned. The pinned `https_origin` is a canonical
HTTPS origin, e.g. `https://ocsp.example.org`, with no credentials, local host,
fragment or nonstandard port. It is **an asserted source identity**, not
cryptographically verified TLS/network origin.

## Real raw WARC/1.1 original profile

Each original WARC file consists of **exactly two uncompressed WARC/1.1 response
records**, first `root`, then `intermediate`. Each has exactly one CRLF-terminated
header block of the eight fields `WARC-Type: response`, `WARC-Target-URI`,
`WARC-Date`, `WARC-Record-ID` (globally unique canonical `<urn:uuid:...>` UUID4),
`Content-Type: application/http; msgtype=response`, `Content-Length` (of the
whole embedded HTTP response), `WARC-Block-Digest` and
`WARC-Payload-Digest` (SHA-256, RFC4648 uppercase base32 without padding,
`sha256:` prefix); followed by CRLF CRLF, exactly `Content-Length` HTTP bytes,
then CRLF CRLF. No other records or trailing bytes.

The embedded response is *exactly* `HTTP/1.1 200 OK` and three headers:
`Content-Type: application/ocsp-response`, `Content-Length` (exact DER body
length), and canonical IMF-fixdate `Date`, then CRLF CRLF and the genuine
issuer-signed EC413 OCSP DER bytes. WARC target URL equals the separately
signed `https_publication_urls[role]`. The WARC/HTTP claimed date equals the
publisher's signed observation UTC in that window. Dates are **claims only**.
No redirects, chunked transfer, gzip, alternate response framing, extensions,
headers or multiple OCSP messages are accepted in this deliberately bounded
profile. The receiver does not fetch URLs or open sockets. WARC limited to
4,200,000 bytes, header blocks <= 8192 bytes and each DER <= 2,000,000 bytes.

## Genuine externally authored signed original observation claims

Each publisher/observer original JSON is exactly:

```json
{
  "schema": "ces.ec414.original_signed_ocsp_observation.v1",
  "claim": {
    "schema": "ces.ec414.signed_ocsp_observation_claim.v1",
    "directory_lineage_id": "<same parent lineage>",
    "epoch_index": 0,
    "window": "historical",
    "witness_role": "publisher",
    "witness_id": "<id from pinned original roster>",
    "event_id": "<globally unique event ID>",
    "claimed_observation_utc": "2026-10-27T00:00:00Z",
    "https_publication_urls": {
      "root": "https://ocsp.example.org/r/root-status",
      "intermediate": "https://ocsp.example.org/r/signer-status"
    },
    "original_lotl_ocsp_bundle_sha256": "<actual EC413 original bundle SHA>",
    "original_signed_lotl_xml_sha256": "<actual original EC410 historical signed LOTL XML SHA>",
    "original_two_ocsp_warc_sha256": "<whole WARC original SHA>",
    "original_ocsp_der_sha256s": {
      "root": "<actual root direct-signed OCSP SHA>",
      "intermediate": "<actual intermediate direct-signed OCSP SHA>"
    },
    "previous_role_receipt_sha256": null,
    "publisher_receipt_sha256": null
  },
  "signature_hex": "<128 lowercase hex characters from original Ed25519 signature>"
}
```

The distinct observer claim has `witness_role: observer`, its own roster ID,
unique event ID and signature, **exactly the same immutable OCSP/WARC/LOTL and
URL claims**, plus `publisher_receipt_sha256` equal to the actual same-window
publisher original SHA. For each signer, `previous_role_receipt_sha256` must
link the previous **actual signed original receipt** across historical,
evaluation and later epochs; it is null only at the first event.

The Ed25519 signature verifies over:

`ASCII("CES/EC414/OriginalOCSPPublicationObservation/Ed25519/v1\\0") || canonical_JSON(claim)`

where `\\0` denotes **one zero byte**, not two printable characters.
Canonical JSON here is UTF-8/ASCII `json.dumps(claim, sort_keys=True,
separators=(',', ':'), ensure_ascii=True, allow_nan=False)`. This only tells
an offline verifier that the private-key holder **signed these claims**;
EC414 never creates any key, source, signed receipt or timestamp in production.

Witness observation claims must fall within the original issuer-signed OCSP
`thisUpdate <= event < nextUpdate`, no more than 7 days after original signed
`producedAt` (with up to 5 minutes of clock-skew allowance). An observer must
claim observation no earlier than publisher minus 5 minutes and no later than
publisher plus 24 hours. Each role's claimed UTC must strictly increase across
windows/epochs; signed event IDs and WARC UUIDs cannot be reused. Authentic
signature with inconsistent *claimed* time causes an **unresolved adverse
coverage flag**, never a positive proof of absolute time. Forged signature,
invalid original payload, wrong cross-receipt or parent reference is denied.

## Source flags / full CLI

Supply **the full EC413 audit flag set** unchanged, including its retained
SHA and all older parents. New required scalar flags:

- `--historical-ec339-lotl-ocsp-publication-bundle-file`
- `--expected-historical-ec339-lotl-ocsp-publication-bundle-sha256`
- `--expected-outside-ec414-publication-witness-roster-sha256`
- `--expected-outside-ec414-publisher-key-sha256`
- `--expected-outside-ec414-observer-key-sha256`
- `--expected-outside-ec414-first-historical-warc-sha256`
- `--expected-outside-ec414-first-evaluation-warc-sha256`
- `--expected-outside-ec414-first-historical-publisher-receipt-sha256`
- `--expected-outside-ec414-first-historical-observer-receipt-sha256`
- `--expected-outside-ec414-first-evaluation-publisher-receipt-sha256`
- `--expected-outside-ec414-first-evaluation-observer-receipt-sha256`

Repeat once per parent epoch in exact order:
`--historical-ec339-lotl-ocsp-publication-epoch-inventory-sha256 <hex>` and
`--minimum-historical-ec339-joint-ocsp-publication-publisher-count <0..2>`.
The **audit** command also requires
`--expected-retained-historical-ec339-lotl-ocsp-publication-inventory-sha256`.
The derive command computes only a local **unsigned** inventory. The actual
outside hash commitments must be sourced independently; derive output may not
be used to fabricate historical witness authority.
