# CES 仓库快捷指令

四个短语是 Codex 对 CES skill 的自然语言调用入口，不是独立的 PowerShell 子命令。执行时读取当前仓库 profile 和 PRODUCT_GUIDE.md；Codex负责分析、补查与编排，CES负责采集、绑定、校验、归档、发布及去重。

另有手动 **仓库知识扩展** 和 **继续仓库知识扩展**，用于空闲时分批扩大知识与技术文档覆盖、记录进度并接续；按需读取[专用规则](<CES-install>/references/knowledge-expansion.md)。不将该模式加入日报/周报定时任务。

## 路由与时间

| 用户短语 | 模式 | 统计范围（仓库配置时区） | 必需报告来源 |
| --- | --- | --- | --- |
| 仓库每日分析 | daily | 当天00:00至本次触发时刻 | 当日提交、构建测试记录、当日既有分析 |
| 仓库周总结 | weekly | 当周周一00:00至本次触发时刻 | 本周所有日报 |
| 仓库月总结 | monthly | 当月1日00:00至本次触发时刻 | 本月所有日报与周报 |
| 仓库年报告 | yearly | 当年1月1日00:00至本次触发时刻 | 本年所有周报与月报 |

“当年从一号”按1月1日解释。显式日期或范围覆盖默认值；未结束周期标明“截至”。使用客户端时间结合仓库时区，不依赖执行主机日期。跨周/月/年时以实际事件日期筛选，不能重复统计跨界子报告。

用户可写“仓库每日分析 <绝对路径>”，或在已有明确仓库上下文里直接写短语。优先使用用户本条指定仓库，其次本对话已确认的仓库，最后与当前目录精确匹配的profile。多个候选或无目标时只问缺少的仓库信息，不能猜私有仓库。profile不能新增授权。

## 共同行为

- 保持CES通用；仓库名、路径、语言/工具链、构建命令及业务规则只来自外部配置和本次输入。
- 区分已有报告覆盖、未分析提交、新增变更、未解决Issue、构建结果及知识陈旧项。保留固定commit、证据哈希、实际命令/退出码和日志引用。
- 启用审计排除策略时，CES自动知识/报告文档发布不计工作提交、代码审计或新增Issue；按发布回执/机器标记及manifest范围核验，不能只凭作者、标题或目录排除。成员正常文档与混合业务提交保留。上级汇总重新过滤旧日报；原归档不改，成品可显示更正投影。只有自动维护提交时有效提交为0，保存仓库构建/追踪状态，不制造个人工作日报。不要因输出文档而递归审计自身提交。
- 明确用户已授权的Issue发布和账号提醒可直接执行并回读；同一报告周期使用现有线程和快照去重。未收到对应外部发布授权时先形成可审阅成品，指出缺少的授权。
- 一次快捷指令仅执行一次，不创建定时器。不能把“自动”解释为无人授权的长驻任务。
- GitHub通知与文档Git发布分开核验。已有明确的长期自动发布授权且profile开启时，增量文档生成后仅自动提交/推送CES托管成品；没有授权的profile默认不执行。不能默认沿用已过期的一次性授权，也不能忽略后续明确的长期授权。保留成员编辑与工作区，不reset、clean、强推或混入无关变更。
- 执行结束给出报告、Issue、知识文档链接，实际分析覆盖，构建测试状态，发布/同步状态和剩余缺口。步骤不满足时继续其他可独立完成的工作，不将失败写成通过。

## 仓库每日分析

1. 采集当天当前分支可达提交，保留作者和committer映射；明确本地与远端差异。不能仅审查HEAD最新一次提交而宣称覆盖当天所有提交。按实际大小拆分证据包，去重merge和同一更改，标记无法读取或超过限额的部分。
   同步后先用audit --config <profile>确认有效提交与自动维护排除项。有效提交为0时保存本轮仓库状态、构建和既有Issue，不为CES自己的推送重新创建代码审阅Finding或个人工作日报。
2. 阅读当日实际代码变更和必要调用链，完成正确性、错误处理、代码质量、安全/兼容性、性能及维护优化检查。复用已有分析；新增结论需重新绑定当前来源，不能机械复制草稿。
3. 分析前按已授权profile执行lifecycle preflight（prepare已内置）：先fetch/ff-only同步，再实际Build。当前部署由用户明确要求仅构建、不运行程序或测试；记录配置、命令、工作目录、耗时、退出码和日志。不能以测试之名启动业务程序、设备或算法样本。缺配置、冲突、分叉、源码未提交等阻塞如实报告；用户确认VS构建正常与本轮退出结果独立保留。
4. 对证据明确的构建/测试问题、代码缺陷、质量与优化机会形成深度Issue，先核对已有Issue去重再按授权发布，追溯对应来源提交和作者，指派/@真实账号。构建错误不能一律归咎于最近作者；未知归属明确列出。没有实际发现时不造问题。
5. 生成按提交人分组的日报，包括已审阅提交、构建/测试结果、问题/建议、待办和覆盖限制；按授权发布GitHub报告并提醒对应账号。
6. 增量维护受当天变更影响的知识章节，保存来源commit/行引用和陈旧标记，成品写入仓库配置目录。

## 仓库周总结 / 仓库月总结 / 仓库年报告

1. 先读取表中整个周期的所有必需来源。每日期/收件人或每周期选择最新有效快照，保留其他来源但去重同一提交、Finding/Issue与知识条目；列出缺报日期和来源缺口。
2. 汇总期间进展、主要模块变化、构建测试趋势、问题与建议、技术债、未解决风险、知识更新和下一周期行动。不是简单拼接报告，也不把提交数解释为个人绩效。
3. **结合代码补充整理分析**：仅围绕报告之间的矛盾、未审阅提交、风险热点、重要架构/接口改动、已修复或仍存疑Issue补查实际代码。无需重做所有历史代码分析；记录补查路径/提交、原因、分析结论与未核验范围。
4. 上级Python汇总命令只负责读取归档，不会自行补查代码。Codex应另行执行必要的Collect/Prepare/Validate并将补充分析保存为独立证据，最终总结引用该证据。不得把固定profile的HEAD^/HEAD~N当作整个周期。
5. 月总结必须同时查阅本月日报和周报；年报告必须同时查阅本年周报和月报。若现有汇总器只消费逐级记录，Codex须另行收集遗漏的日/周报告并形成显式补充输入，不能把“只看月报”声称成“已看全年周报和月报”。无中间报告时可生成明确标注不完整的来源集合，不得静默丢掉可用记录或从零伪造日报。
6. 可用ces.period_synthesis.v1承载现有绑定字段与综合评述。补充代码证据及额外报告清单单独保存并在正文引用；不要任意向严格schema塞入未知字段或伪造哈希。
7. 汇总结果提交到相应周期的GitHub报告Issue。补查发现的新问题另建/更新问题Issue，并在总结里链接；不把优化建议混成已证明故障。按已有权限通知维护人，回读发布内容。
8. **优化整理一轮知识文档**：结合整个周期的已确认结论去重重复章节、校正失效约定、更新模块/接口/算法/构建/决策/已知风险等受影响内容，保留引用和版本。内容尚未核验则标记待验证，不改写成员编辑，不把整理理解为重写全部文档。
9. 文档成品在仓库内，缓存与发送账本在仓库外。Git同步依据本次或长期明确授权独立执行。

## 构建测试配置

如profile提供build_validation.steps，按其显式参数列表运行；可复用用户已确认的IDE/开发环境配置。每步包含name、argv、cwd、timeout_seconds、kind（build/test）等信息。命令由外部配置承载，不写入CES产品源码。

没有构建命令时，检查仓库维护说明与已安装开发工具，准备具体候选命令；仅在目标/配置/输入无法确定时询问缺失信息。不得仅凭工具不在PATH断言本机坏了；不得执行需要硬件、交互界面、破坏数据或额外凭据的未知测试。无可靠可执行配置时记录“构建测试待配置”，继续当日代码分析、报告与知识维护。不得把未执行算通过。

这里是Codex编排约定；若CLI尚未实现某个步骤，Codex按授权直接运行可复用工具并保存日志，不宣称产品子命令已自动执行该能力。


## Issue持续闭环（所有快捷指令）

每次分析先按profile同步源码并实际Build（不运行程序/测试），然后track sync --config <profile> [--execute]；即使没有新提交也同步CES代码问题，保留状态/负责人/评论/PR或commit变化与未知读取。默认7天无实质进展才提醒，冷却7天，首次基线不刷屏。报告Issue不能当作待修缺陷。
对修复候选、关闭未验证、重新打开或相关源码变化的Issue，用track prepare固定最新远端HEAD与实际相关路径，由Codex复核并track review保存结论。当前profile明确禁止runtime tests，不能调用track test；实际Build结果单独记录，不能替代运行验证。旧HEAD、脏工作区或未配置命令不得冒充通过。允许的源码同步只有分析前fetch/ff-only，遇冲突不pull覆盖、不reset。
将open/not_fixed/in_progress/fix_candidate/closed_unverified/resolved_verified/regression_suspected/unknown分别写入日报、周期报告和仓库问题状态文档。当前Issue记录与下一步由documents导出到docs/ces/issues/README.md，提交推送仍需对应授权。
自动关闭/重开默认关闭，先给有证据的预览；只有配置独立启用且当前来源和必需测试满足fixed/regression评审时可track transition，回读后再次同步。完整规则见./ISSUE_TRACKING.md。


## 自动同步、实际Build与知识发布

当前已获授权的项目profile使用lifecycle preflight：每次分析前ff-only同步远端，构建整个解决方案的已确认配置。不改写VS工程或升级工具链；构建本身允许正常的编译/链接/打包步骤，但不执行生成的程序或测试。

知识和报告在仓库内增量写出后，knowledge publish --execute及documents --execute按profile持续授权自动提交推送manifest托管文件。不能把代码、构建产物、日志、缓存、凭据或用户编辑混入文档提交。远端推进、文档冲突或暂存用户改动会停止，不强推。详情见./AUTOMATIC_LIFECYCLE.md。
